# TIMEVERSE Delivery Roadmap

Each phase requires a working implementation, tests, documentation and manual verification before being marked complete.

## Phase 0 — Research and product definition
- Competitor/prior-art audit.
- User problem interviews and validation.
- Choose the narrow MVP.
- Identify lawful, sustainable data sources.

Exit: written research findings, risks and approved MVP scope.

## Phase 1 — Repository and application foundation
- Monorepo structure and developer documentation.
- Next.js frontend shell.
- FastAPI backend shell.
- Health endpoint and frontend-to-backend connection.
- Environment configuration and error handling.
- CI for linting, type checks and tests.

Exit: clean local install, running frontend/API and passing CI.

## Phase 2 — Premium interface
- Responsive dark-luxury design system.
- Floating navigation and dashboard shell.
- Search and watch detail layouts.
- Loading, empty, error and offline states.
- Keyboard accessibility and mobile layout.

Exit: real navigation and working interface, not static mockups.

## Phase 3 — Catalogue and evidence
- Brand/model/reference/variant data model.
- Curated starter dataset with documented provenance.
- Search, filters and exact-reference pages.
- Claim-level evidence and conflict display.

Exit: every factual catalogue claim is sourced or explicitly labelled.

## Phase 4 — Comparison and discovery
- Side-by-side comparison.
- Unit normalization and variant mismatch warnings.
- Saved watches and collections.
- Explainable recommendation foundations.

## Phase 5 — Fit and ownership
- Wrist fit approximation with caveats.
- Ownership cost assumptions and scenarios.
- Purchase, warranty, condition and service records.
- Export and privacy controls.

## Phase 6 — Education and media
- Watchmaking learning modules.
- Licensed product media.
- Optional AI-generated illustrative scenes, clearly labelled.
- Video creation only where a real permitted provider/workflow exists.

## Phase 7 — Market intelligence and release
- Verified offer/price adapters where permitted.
- Currency, geography, seller and timestamp provenance.
- Deployment, monitoring, backups and operational documentation.
- Accessibility, privacy and security review.

## Definition of done
A feature is complete only when UI, API/data behavior, validation, error states, tests, docs and manual verification are all present. No fake live data or placeholder actions presented as finished functionality.
